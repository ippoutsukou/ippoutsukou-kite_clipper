# kite-clipper 動画専用UI見直し案
作成日：2026-09-12／状態：実装前の提案。アプリコード・既存仕様書は変更していません。

## 目的と前提
動画を選んだ後に工程を進めるための操作を減らし、30本程度でも確認と修正に集中できる体験を目指します。
対象は現行Windows PCアプリです。参照サイトのiPhone/iPad版をそのまま移植する案ではありません。
写真機能は、追加・分析・管理・出力・関連UIを新仕様から除外します。既存の写真データを削除する指示ではありません。
スマホ→PCの転送は今回の変更範囲外です。この負担そのものは残ります。
画像は実装前の生成モックです。動画・ファイル名・人物名・数値はダミーです。

## 通常の操作
1. 「動画を選択…」からWindows標準ダイアログで複数動画を選びます。
2. 自動的に候補画面へ切り替え、サムネイル生成→AI採点→区間提案→仮採用まで進みます。
3. 候補をざっくり確認し、不要な候補だけ外して「切り出し実行」を押します。
4. 高速コピーで作ったクリップの動画プレビューを自動表示します。
5. 同じ画面で候補の切替、前後範囲の調整、除外、並べ替えができます。
6. 「個別ファイルで保存」または「1本にまとめて保存」で採用中のクリップを保存します。
タグ付けは4〜5の画面にある任意ボタンからだけ開きます。通常の流れでは通りません。

「フレーム生成」「AI採点を実行」「AIおまかせ」「選別ビュアーを開く」を工程操作として出しません。
切り出し実行はユーザーが残す明示操作です。動画追加だけで全クリップを書き出す方式にはしません。

## 候補一覧とプレビューの操作
- 候補カードは1枚のフレームではなく「動画の区間」を表します。代表サムネイル、前後の小サムネイル、元動画名、区間、長さを表示します。
- チェック操作は採用／除外。カードの画像部分を押す操作はプレビュー。二つを混同させません。
- 通常はまとめて「切り出し実行」。個別カードを先に押した場合は、その候補だけプレビュー用クリップを自動準備し、同じ04画面で見られるようにします。未準備の他候補は開いたときに準備します。追加の確認ダイアログは出しません。
- 個別プレビューから保存を押した場合も対象は採用中の全候補です。未準備分は保存処理内で準備します。フッターに「採用中のN候補を保存」と明示します。
- 候補一覧へ戻っても、採用状態、調整範囲、タグ、再生対象を保持します。
- 除外は候補の採用状態だけを変更します。元動画・保存済み動画は削除しません。「除外した候補」から戻せます。
- 並び順は選択した元動画の一覧順→動画内の開始位置順を安定した初期順とし、左のリストで並べ替えます。実装ではキーボード操作でも並べ替え可能にします。
- 「すべての動画」はAIが拾わなかった場面を手動追加するための補助タブです。通常はAI候補だけを表示します。
- AIが出した候補を自動で良い結果と確定しません。候補ゼロを成功クリップとして水増ししません。
- タグ入力は05画面に限定します。人物・トリックを任意で付与し、各タグは再クリックで解除できます。新規名は同じ画面の入力欄で追加します。モックの「タグを外す」は実装時には一回操作のボタンとし、永続状態のスイッチにはしません。
- タグはローカルな作業情報に保存します。個別出力のファイル名に安全な文字へ変換して反映し、同名を避けます。結合では区間とタグの対応を作業情報に保持し、映像へ焼き込みません。

## 高速コピーと範囲調整
標準保存経路は映像・音声とも再エンコードなしです。「高速コピー」チェックボックスは置きません。
サムネイル生成や画面での動画再生にはデコードが必要ですが、保存する映像の再エンコードとは区別します。

任意フレームでの正確な開始・終了を、高速コピーだけで保証することはできません。
FFmpegの公式説明では、stream copy時にはシーク点と指定位置の間の区間が残る場合があります。
したがって本案では次を採用します。

1. 元動画のタイムスタンプ・ランダムアクセス可能な境界を事前解析します。
2. タイムラインのハンドルや時刻入力は、有効な切り出し位置へ合わせます。連続的にフレーム精度で切れるような表現はしません。
3. 要望範囲と保存に使う実効範囲を内部で区別します。通常の表示は実効範囲です。
4. ドラッグを離してから短い待機を挟み、変更した候補だけ元動画から再度高速コピーします。再切り出しボタンは不要です。
5. 再生成中は「プレビュー更新中」と表示。旧プレビューを最新結果として見せません。最新世代の結果だけを反映します。
6. 実ファイルを再解析し、再生可能性・実時間・開始終了・音声を確認した結果をプレビューします。
7. 元動画を参照し続けるため、一度短くした候補も元動画の範囲内なら伸ばせます。
8. 正常な範囲を作れない素材は該当候補に理由を表示します。再エンコードへの無断切替はしません。

キーフレーム位置だけであらゆる形式の正確な終端・音声同期が保証されるわけではありません。
Bフレームや音声パケットの境界を含め、対応形式別の実ファイル検証が必要です。
画像中の時刻はレイアウト例であり、秒数や集計値の画面間の一致は保証しません。実装では出力検証済みの値を一元表示します。

## 個別保存と結合保存
- 保存対象は、採用中の全候補の最新範囲・順序です。現在表示中の1件だけではありません。
- 初回は保存先のOS標準ダイアログを使います。前回フォルダーを初期位置にし、設定ウィザードは追加しません。
- 未変更の準備済みクリップは再利用します。プレビュー用と保存用で同じ範囲を使い、重複した全件処理を避けます。
- 元動画と既存出力を上書きしません。新しい名前で保存します。
- 結合前にストリーム構成、コーデック・設定、解像度、タイムベース、音声仕様、回転情報などの互換性を確認します。同じ拡張子だけでは判定しません。
- 結合可能と検証できたものだけ、再エンコードなしで結合します。結果の再生時間・音声・接続部を検証します。
- 非互換時は08のインライン表示を使い、結合ボタンを無効にします。採用候補は勝手に除外せず、個別保存を残します。
- 縦横混在のサイズ統一、クロップ、BGM、テロップ、トランジションは本仕様に含めません。
- 全件保存できた場合だけ完了表示にします。一部失敗時は成功件数と失敗対象を分け、失敗分を再試行できます。

## 解析・例外・再開
- 解析とコピーはUIを止めずに実行します。動画ごとに進捗を出し、候補は準備できた順に追加します。
- 通常は解析完了後に「切り出し実行」を有効化します。中断した場合は処理済み分を保持し、「解析を再開」または「準備済み候補で進む」を同じ画面で提示します。
- 読み取り失敗、素材移動、変更検出、空き容量不足は該当素材／処理に表示し、復旧操作を近くに置きます。正常な他素材の解析は続けます。
- ファイルが見つからない場合は「場所を指定」。同名だけで自動的に別動画へ差し替えません。
- 元動画の変更が見つかった場合は旧生成物を使った保存を止め、再解析を案内します。
- AIモデル未準備時は学習作業を通常フローに挟みません。配布時に対応モデルを用意し、欠損時は明示したうえで手動候補追加を使えるようにします。
- 作業は自動保存します。元動画識別子、参照先、変更検出情報、候補ID、実効範囲、採用状態、並び順、タグ、生成物の世代を保持します。
- 元ファイルの参照方式は旧仕様案の基盤を利用できます。今回の作業以外の既存inputフォルダーを無条件に取り込まないようにします。
- 素材の登録解除や候補除外は論理操作です。不要ファイル整理を通常の完了条件にしません。
- システムのファイル選択／保存先ダイアログはOS標準を使います。10の絵は配置イメージで、実際の見た目はWindows設定によって変わります。

## 実装上の成立条件
既存のPython／FFmpegによる抽出・AI候補生成・切り出しを活用する想定です。
画面はボタン、一覧、サムネイル、二つのハンドルを持つタイムラインで構成できます。
ただし、音声つき動画を画面内で再生・シークするバックエンドの追加／統合が必要です。Tkinterの画面配置変更だけで完了する改修ではありません。
具体的な再生基盤は、Windows配布版での対応コーデック・シーク・音声同期・ライセンス・同梱サイズを確認して決めます。本検討では新規依存は追加していません。
サムネイルをクリックして静止画を開くだけの実装では04の要件を満たしません。

優先順：
1. 動画専用の入口と、自動解析→候補一覧。
2. 候補一覧と共通状態を持つ動画プレビュー、除外、範囲調整。
3. 検証付き高速コピー、個別保存、互換性チェック付き結合。
4. 任意タグ画面と再開・失敗復旧。

## 受入確認
- 動画選択後、生成・採点・ビューア起動のボタン操作なしで候補一覧に到達する。
- 候補をざっくり確認して切り出し実行すると、動画プレビューが自動で開く。
- 候補カードからの個別プレビューも同じ画面でできる。
- 範囲変更後、追加ボタン操作なしで最新プレビューへ更新される。
- 短縮後の拡張、元動画端の制限、開始≧終了の防止、連続ドラッグ時の古い結果排除を確認する。
- 除外・復帰・並べ替え・戻る操作で採用内容が失われない。
- タグ画面はボタンを押すまで表示されない。タグなしで両保存経路を完了できる。
- 保存対象件数と実ファイル数が一致する。結合結果の順序が左一覧に一致する。
- 保存経路に映像・音声エンコーダーを使わず、出力映像の開始・終了とプレビューが一致することを対応形式別に確認する。
- 同形式／非互換混在、音声なし、スマホの可変フレームレート、縦動画の回転、Bフレーム、長いキーフレーム間隔、元動画切断、容量不足を確認する。
- 30本程度の同じ素材・同じ成果物で、手作業／現行版／新UIの操作時間・完了時間・修正回数・取りこぼしを比較する。
