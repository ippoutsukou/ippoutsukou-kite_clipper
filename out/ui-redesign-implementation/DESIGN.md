## 1. 要件定義
目的：動画選択からAI候補表示までの工程ボタンをなくし、動画確認・範囲調整・除外・保存を同じ主画面で行う。
対象：WindowsデスクトップGUI、動画素材の参照、AI区間生成、音声付き埋め込み再生、高速コピー、個別・結合保存、任意タグ、必要なCLI接続、文書・テスト。
非対象：写真入力と写真整理、スマホ転送、クラウド、再エンコードによる整形、公開・コミット・既存ファイル削除。
写真機能はGUIだけでなく通常処理経路から外す。内部フレーム画像の読み取り・分析は維持する。
制約：既存ユーザー変更と未追跡成果物を保護する。認証情報と実ユーザー素材は読まず、テストは合成動画のみ。ネットワーク・追加インストールは行わない。
成功条件：原仕様の通常フローが操作可能、実際の動画と音声の再生、調整後の実クリップ確認、採用対象のみの安全な保存、非互換結合の拒否、作業復元。

## 2. 仕様
入力：対応拡張子の動画をOS標準ダイアログで選択。元ファイル参照を登録し、無条件コピーはしない。
出力：作業情報、フレーム、プレビュークリップをout/sessions/<session_id>/へ分離。ユーザーが選択した保存先への出力はアプリ実行時の明示操作により行う。
画面：入口→解析中／候補一覧→切り出し中→プレビュー→保存中／完了。タグのみ任意遷移。候補ゼロは同じ画面から手動追加。
操作：チェックは採用切替、画像クリックは個別プレビュー。左一覧は順序変更と除外復帰。タイムラインは境界調整。下部2ボタンは採用中の全候補を保存する。
戻る・タグ遷移で選択と再生対象・範囲・順序を保持する。UIにフレーム生成・AI実行・ビューア起動を残さない。
例外：参照切れは再指定、変更素材は旧生成物保存禁止、候補ゼロは手動、容量不足／一部失敗は対象を分けて再試行、再生不可は明示する。
保存：UTF-8 JSON（BOMなし）を一時ファイルから原子的に確定。壊れた既存状態を空データで上書きしない。
ダミー例：sample_01.mp4、ライダーA、ジャンプ。実ユーザー素材はテストに使用しない。

## 3. 技術スタック
Python 3.13.5、Tkinter 8.6、既存OpenCV/numpy/scikit-learn/onnxruntime、同梱FFmpeg/ffprobe。
配布：既存PyInstaller構成を更新し、新モジュールを取り込む。今回コミット・公開はしない。
動画再生：MCI初期案は合成MP4のopenに失敗したため採用せず、実装は同梱FFmpegの映像デコードとWindows waveOutのPCM再生を使用する。Tkの表示更新は主スレッドのqueue pollingで行う。
再生基盤：video_preview_backend.pyとwave_audio.py。合成H.264/AAC動画でopen・play・pause・seek・EOF後再開・resize・closeを確認済み。新しい外部依存は追加しない。保存経路は引き続きstream copyのみ。
Windows以外ではAPIのロード失敗で全体がimport不能にならない構造とする。

## 4. 設計
### 4.1 責務
- kite_clipper_gui.py：起動と画面、ユーザー操作、main thread上の状態更新。既存AI子プロセス起動の互換性を保持する。
- 新規セッション／処理モジュール：素材と候補モデル、安全な作業保存、解析、切り出し、互換性確認、保存。
- video_preview_backend.py（仮）：埋め込み動画デバイス、再生・一時停止・シーク・終了・エラー。
- kite_clipper.py：必要な既存動画処理を再利用。写真の通常入力処理を除外する。
- frame_scorer.py：必要に応じ、作業rootとモデル資産rootを分離して利用できる小さなI/F変更を行う。既存学習・競技切替は維持。
ファイル名の細部は実装担当の判断で調整可。ただしGUIへ全責務を集中させない。

### 4.2 データモデル
素材：不変ID、表示名、元パス、登録サイズ・更新時刻、長さ、映像／音声ストリーム情報、切り出し境界、状態。
候補：不変ID、素材ID、要望範囲、実効範囲、採用状態、順序、人物・トリック、変更世代、プレビュー生成世代・パス、検証済み再生時間。
セッション：schema_version、session_id、競技、素材一覧、候補一覧、現在画面・対象、保存先履歴。
素材名のみを識別子にしない。UUID等を用い、同名動画と再登録を混同しない。
モデルとCLIP資産はアプリ配置root、生成物はセッションrootへ。前回作業のinputを勝手に混ぜない。

### 4.3 非同期処理
Tkの変更はmain threadだけ。workerは結果queueへ通知し、afterで反映。
操作開始時に対象IDと世代を固定。連続調整後の古い結果は新しい状態へ適用しない。
UI終了・処理中断で子プロセスを停止し、完了イベントを二重適用しない。
時刻変更をdebounceして変更した候補だけ元動画から再切り出し。確定前の旧画像を最新プレビューと表示しない。
解析中もUI応答を保持し、準備できた候補から表示する。

### 4.4 高速コピー
保存の映像・音声は-c copy。デコードはサムネイル／画面再生にのみ使用する。
任意フレーム境界の精度は保証せず、シーク可能な境界へ合わせた実効範囲を明示する。
Bフレーム・音声境界・非ゼロ開始時刻を含む検証が必要。出力をffprobeし、時間・ストリーム・再生可能性を確認する。
再生用クリップを調整後保存にも利用して、見た結果と保存結果を一致させる。元動画を保持するため拡張も可能。
結合はコーデック／ストリーム構成／時間基準／解像度／音声／回転等を比較し、非互換を拒否。拡張子一致だけで判定しない。
新規ファイル名と未完成名を用いて既存出力と元動画を上書きしない。失敗出力を完成扱いにしない。

### 4.5 再生の検証状況
合成MP4（H.264＋AAC、短い動画）でFFmpeg映像デコードとwaveOut PCM再生のopen・親ウィンドウ表示・play・pause・seek・位置更新・EOF後play再開を実行済み。無音動画も受理する。回転／縦動画と非対応コーデックは再生エラーをUIへ表示する。

## 6. 確認計画
標準unittest等の既存環境で、状態復元・範囲整合・採用数・互換性・ファイル保護を検証。
合成音声付き動画、無音動画、異形式、同名パス、Bフレームとキーフレーム間隔のケースで実FFmpegを使用する。
GUIはテスト用セッションだけを使い、実素材・既存作業状態へ触れない。表示・クリック導線・再生・シーク・任意タグの遷移を確認する。
テスト出力はout配下に保持し、既存ファイル削除は行わない。未検証の配布端末性能や30本のユーザー時短効果は実証済みと主張しない。
