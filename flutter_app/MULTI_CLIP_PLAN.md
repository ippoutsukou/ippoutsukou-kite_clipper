# 次段階：複数動画の一覧と切り替え（承認待ち）

## 1. 要件定義
- 目的：動画を選び直さずに、一覧から切り替えて各動画の範囲を調整する。
- 対象：Windows / Android、手動選択したローカル動画。
- 初期範囲：1動画につき1区間。最大30本を提案し、超過は追加前に説明する。
- 非対象：AI解析、1動画から複数区間の作成、タグ、結合、一括保存、アプリ再起動後の復元。
- 成功条件：Aの範囲を変更→Bを編集→Aへ戻った際に範囲が保持され、現在の動画だけ保存できる。
- 原本と保存済み動画を変更・削除しない。外部送信しない。

## 2. 仕様
- 「動画を追加…」で複数選択。選択順に追加し、既存一覧は置換しない。
- 同じパスの重複は追加しない。別パスにある同名ファイルは別項目として扱う。
- 追加をキャンセルした場合は一覧・選択・範囲を維持。
- PCは左一覧、Androidは一覧を開くボタンと選択用シートを使用し動画の高さを維持。
- 一覧にサムネイル、名前、区間長、選択状態を表示。長さ未取得は「未確認」とし推測しない。
- 項目を選ぶと元動画を開き、保存していた開始位置で一時停止する。
- 開始・終了は動画ごとに保持する。エラーと保存結果も動画をまたいで混ぜない。
- 保存ボタンは「このクリップを保存」。全件保存と誤認させない。
- 一覧から外す操作は作業一覧だけに作用。最後の項目を外したら初期画面へ戻る。
- 除外・並べ替えは最小版の切替検証後に追加し、ファイル削除と区別する。
- 未対応動画は項目にエラーを表示し、他の動画の編集は維持。
- 読み込み・保存中は追加／切替／除外を無効化。非同期結果を別動画へ反映しない。

## 3. 技術スタック
- Flutter / Dart、既存file_selector・media_kitを継続。新規依存は予定しない。
- Windows FFmpeg、AndroidのAAC/PCM音声対応を含む保存処理は維持。
- 配布はWindowsテストビルドとAndroid APK。

## 4. 設計
- ClipItem：内部識別子、入力パス、表示名、長さ（未取得はnull）、範囲（未取得はnull）、代表画像、エラー、保存結果。
- ClipSession：順序付き項目リストと現在選択。範囲更新・追加・切替をモデルへ集約。
- 再生プレーヤーは1つだけ。動画ごとに作らない。
- 切替前に現在の状態を確定し、準備待ち→動画を開く→長さを確認→保持範囲を復元→開始位置へシーク。
- 非同期イベントは世代管理し、前の動画のduration・サムネイル・エラーを混入させない。
- 連続サムネイル8枚は選択中のみ保持。全動画を同時デコードしない。
- この段階の編集状態はメモリ内のみ。終了で失われることを案内する。

## 5. タスク（コミット単位）
1. ClipItem / ClipSessionと範囲保持・重複・上限の単体テスト。
2. 複数選択、一覧、切替を現在のUIに接続。
3. 遅延読み込み・失敗・キャンセル・旧イベント混入の回帰テスト。
4. Windows / AndroidでA→B→Aの範囲保持と現在項目の音声付き保存を確認。
5. 確認後に一覧内の並べ替え・取り外しを安全化して追加。

まず1〜4の最小版を実装する提案。AI・結合・一括保存は別途仕様を合意する。
