# 1本にまとめて保存（承認前の案・2026-09-18）

## 1. 要件定義
- 目的：複数の動画から選んだ区間を、順番につないだ動画1本として保存する。
- 対象：Flutter の Windows / Android（利用者の決定）。
- 利用者の決定（2026-09-18）：
  - 対象環境：Windows と Android の両方。
  - 画質：形式がそろっていれば無劣化でつなぐ。違う場合は確認を出してから作り直す（再エンコード）。
  - 順番：動画一覧の並び順、同じ動画の中は区間番号順。全区間が対象。
- 非対象：結合画面での区間の選択・並べ替え（一覧の「上へ」「下へ」で調整する）、
  場面転換の効果、音楽の追加、既存の「すべて保存…」（1区間1ファイル）の変更。
- 制約：元動画は変更しない。保存先は利用者が選ぶ。
- 成功条件：
  1. 2本の動画の計3区間を、順番どおりにつないだ1本が保存される。
  2. 形式がそろっていれば無劣化（作り直しなし）で保存される。
  3. 途中で失敗・中止しても、元動画と一覧の区間は変わらず、理由が分かる。

## 2. 仕様
### 画面
- 下部の「すべて保存…」の左に「1本にまとめて保存…」を追加。区間が2個以上あるときだけ押せる。
- 押すと確認ダイアログ：
  - つなぐ順番（動画名・区間番号・長さ）と、合計の長さ・本数。
  - 画質の扱い：「無劣化でつなげます」または「形式が違うため作り直します（時間がかかり、画質は少し落ちます）」。
  - 保存先を選んで実行（Windowsはフォルダ選択、Androidはフォルダ選択画面）。
- 進捗ダイアログ：「3区間中 2区間目を準備中」「つないでいます」と中止ボタン。
- 終了後：保存先とファイル名、所要時間、作り直したかどうかを表示。

### 動き（Windows）
1. 区間ごとに一時ファイルへ切り出す（既存の切り出しと同じ・無劣化）。
2. 全部の形式（符号化方式・解像度・フレームレート・音声）を調べる。
   - そろっている：`concat` で無劣化につなぐ。
   - 違う：確認を得たうえで、同じ解像度・フレームレートにそろえて作り直す。
3. 一時ファイルは成功・失敗にかかわらず削除する。

### 動き（Android）
- 端末の仕組み（MediaMuxer）で、区間を順につないで1本に書き出す。
- 形式がそろっていない場合は作り直しができないため、実行前に「この端末ではつなげません。
  形式のそろった動画だけを選んでください」と伝えて中止する。

### 例外
- 区間が1個以下：ボタンを押せない。
- 8:7素材（5312x4648）など H.264 の上限を超える組み合わせ：作り直しができないため、
  無劣化でつなげない場合は理由を示して中止する。
- 空き容量不足・保存先が消えた：途中で止め、未完成ファイルの場所を伝える。
- 元動画が見つからない区間：その動画を含めずに実行するか中止するかを確認する。
- 中止：書きかけの出力を消し、元動画・一覧は変更しない。

## 3. 技術スタック
- Windows：同梱予定の FFmpeg（現在はPATH上のもの）。`concat` と、作り直し時は
  Python版と同じ考え方（解像度に応じたビットレート、H.264上限の判定）。
- Android：既存の MediaExtractor / MediaMuxer と PcmAac（音声変換）を拡張。
- 新しい依存追加はしない。

## 4. 設計
- `lib/merge_plan.dart`（新規）：つなぐ順番の組み立てと検査（区間数・合計長さ・元動画の有無）。
  画面から切り離し、単体テストできる関数にする。
- `lib/merge_service.dart`（新規）：Windowsの切り出し→形式の照合→つなぐ処理、Androidはネイティブ呼び出し。
- `lib/export_service.dart`：一時ファイルの作成・削除と、既存の切り出し処理の共有部分を使う。
- `MainActivity.kt`：`merge` を追加（複数の区間を1つの MediaMuxer へ書き出す）。形式の照合もここで行う。
- `lib/main.dart` / 新しいダイアログ：ボタン・確認・進捗・結果。

## 5. タスクリスト
1. つなぐ順番の組み立てと検査、単体テスト。
2. Windows：形式の照合と無劣化つなぎ、実動画での確認。
3. Windows：形式が違う場合の作り直し（確認ダイアログ付き）。
4. Android：ネイティブの結合と形式の照合、実機確認。
5. 画面（ボタン・確認・進捗・結果）と、中止・失敗時の後片付け。
6. 静的解析・テスト・両OSビルド、利用者による確認。

## 6. 進め方の提案
- まず 1・2・5 の最小実装（無劣化のみ）で動作確認 → 次に 3（作り直し）→ 4（Android）の順で進める。
- 各段階でコミットし、そのつど実画面で確認する。

- `lib/export_service.dart`：切り出しとツール検索を共有できるよう公開（ffprobe の検索も追加）。

- 検証：静的解析成功、テスト112件成功（結合9件追加。実動画で2区間の無劣化結合と、

## 進捗2：Androidの結合（2026-09-18・ビルド0918-0909）
- タスク4を実装。3（Windowsでの作り直し）は未着手。
- `MainActivity.kt`：`merge` を追加。保存先ファイルを選んでから、区間を順に1つの MediaMuxer へ書き出す。
  - 先にすべての区間の形式（映像の形式・大きさ・音声の形式/サンプリング/チャンネル）を照合し、
    1つでも違えば何も書かずに中止する（理由を日本語で返す）。
  - 区間ごとに「要求した長さ」分だけ時刻をずらす（音ズレ・重なりを防ぐ）。
  - PCM音声（audio/raw）はまとめられないため、その旨を返す（1件保存では従来どおりAACへ変換する）。
  - 失敗時は書きかけの出力を削除する。進捗は `mergeProgress` で区間単位に通知。
- `lib/merge_service.dart`：`mergeAndroid` を追加。保存先を選ばずに閉じた場合は中止扱い。
- `lib/main.dart`：Androidでもボタンを表示。処理中は画面の消灯を防ぐ。中止ボタンは出さない
  （端末側の処理を途中で止められないため）。
- 飾りだったヨットアイコン（画面左上）を削除。
- 検証：静的解析成功、テスト116件成功（Android呼び出し4件追加）、Windowsビルド成功、APKビルド成功。
- 未確認（利用者確認待ち）：Android実機での結合（同じ端末で撮った動画同士／形式が違う場合の中止）。
