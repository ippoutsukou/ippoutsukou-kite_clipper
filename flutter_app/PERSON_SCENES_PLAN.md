# 人物シーンの提案（下書き）

状態：要件整理中（2026-11-23）。実装は未着手。

## 1. 要件

### 目的
YouTube向けに「その日の様子がわかる動画」を作れるようにする。カイトに乗っている場面だけでなく、
スクールの風景や海に来た人たち、表情がわかる場面（笑顔・ピースサインなど）も区間として提案する。
（テスターの意図。トリック集ではなく、その日の記録動画が目的 2026-11-23）

### 考え方（案）
「良い場面を探す」と「使えない映像を捨てる」の2つに分けて考える。
- 拾う：カイト（既存モデル）／人物・スクール風景（今回追加）
- 捨てる：地面だけ・ブレ・真っ暗・ポケットの中など（既存の kite_static は除外用途で実績あり）

### きっかけ
テスターから「88本を解析してまとめたら、そのまま出力された」との報告。kiteモデルの提案が0個の動画は
全長の初期区間が残り、まとめる対象に入っていた（別件として「提案0個の扱い」を直す。§5）。

### 対象
- Windows版（Android版は同じ仕組みで後から対応できる見込み。今回は未確認）
- AI解析（手動）とおまかせモード

### 非対象
- 顔の個人識別（誰が写っているか）
- 動画の音声（歓声など）
- 1秒より短い一瞬の動作を確実に拾うこと

### 決定事項
- 「カイト」と「人物」の提案は**分けて出す**（ユーザー決定 2026-11-23）。
- 人物の提案で拾うのは**人が写っている場面全般**（スクール風景・海に来た人・表情など）。
  海の景色だけの場面は判定対象にしない（ユーザー決定 2026-11-23）。

### 成功条件（案）
- 近距離で撮った笑顔・ピースの場面が、人物の提案として出る（検証用動画で目視確認）
- カイトの提案の結果は今と変わらない
- 解析時間の増加はわずか（CLIPの計算は共通のため）

## 2. 仕組み（現状の確認結果）
- 各コマを CLIP ViT-B/32 の画像エンコーダーで512次元にし、競技ごとの線形モデル
  （`assets/models/*.json` の `coef` 512個 + `intercept`）で点数化している。
- 他の競技モデルも同じ埋め込みで同時に採点している。人物モデルも同じ形の JSON を1つ足せば、
  解析処理はほぼそのまま使える。
- 区間化はヒステリシス（enter / exit）と前後の余白で行うルール処理。

## 3. 作り方の候補

### 方式A：言葉で指定（ゼロショット）
- 「笑顔の人」「ピースサインをする人」などの文を CLIP のテキストエンコーダーで512次元にし、
  その向きを `coef` として JSON に書き出す。教師データは不要。
- **必要なもの**：テキストエンコーダー。2026-11-23 に承認を得て取得済み
  （`vendor/clip/text_model_quantized.onnx` と `tokenizer.json`、記録は `vendor/clip/SOURCE_text.txt`）。
  `.venv` に `tokenizers` 0.23.3 を追加。アプリには同梱しない（JSON に結果だけ入れる）。
- 動作確認済み：文を入れると512次元が出る（形は画像側と同じ）。
- 未確認：実際の動画のコマで、人が写っている／いないを点数で分けられるか。検証用動画が必要。
- 点数の目安（enter / exit）は検証用動画で決める。

### 方式B：教師データで学習
- 既存の競技モデルと同じ手順（フレームに「使う／使わない」を付けて学習）。
- 精度は出しやすいが、データ作りの手間がかかる。

## 4. 既知の制約
- 解析画像は短辺224に縮めて中央を切り抜く。遠くの人や画面端の人は顔・指が数ピクセルになり、判別は難しい見込み。
- 解析するのは約1秒ごとのキーフレームだけなので、一瞬のポーズは取りこぼすことがある。

## 5. 関連：提案0個の動画の扱い（2026-11-25 案1の形で実装。OMAKASE_PLAN.md 末尾参照）
- 現状：提案0個だと全長の初期区間が残り、「1本にまとめて保存」「すべて保存」の対象になる。
- 案1：提案0個なら初期区間を消し、一覧に「提案なし」と表示する。
- 案2：区間は残し、保存前に「提案なしの動画がN本あります。含めますか？」と確認する。
- 人物の提案を入れる場合は、「カイトも人物も0個」のときにこの扱いを適用する。
