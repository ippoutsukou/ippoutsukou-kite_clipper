# AI候補の提案：速度測定用の最小実装（ビルド14）

利用者の方針（2026-09-16）：スマホ単体で完結させたいため、AI解析は端末内で行う。ただし Android の速度が未知なので、作り込む前に速度だけを測る。

利用者承認済み：
- ONNX Runtime（Android版）の追加 `com.microsoft.onnxruntime:onnxruntime-android:1.20.0`（Maven Central から取得）。
- CLIPモデル（約85MB、MITライセンス）のアプリ同梱。APKはその分大きくなる。
- この段階は Android のみ。Windows は対象外（別途 ONNX Runtime の同梱が必要なため）。

## 既存Python版の処理（移植元）
1. 1秒ごとにフレームを取り出す（profiles の cv.frame_interval）。
2. CLIP ViT-B/32 画像エンコーダー（ONNX量子化・約85MB）で512次元の埋め込みを作り、L2正規化。
3. ロジスティック回帰（競技ごと・係数512個と切片のみ）で採用確率を出す。
4. 移動平均（窓3）で平滑化し、ヒステリシス（enter/exit）で区間化。前後に余白（pre_roll/post_roll）。

## 測定用実装の内容
- assets/models/<競技>.json：既存の学習済み `.pkl` から係数・切片・しきい値・余白を書き出したもの（各約5.5KB）。kite / wing / windsurf / kite_static の4競技。書き出しは PC 上の Python で実施（models/*.pkl は変更していない）。
- assets/clip/vision_model_quantized.onnx：vendor/clip からコピー（内容一致を確認）。SOURCE.txt も同梱。
- lib/ai_segments.dart（純Dart・テストあり）：判定モデルの読み込みと検証、採用確率の計算、移動平均、ヒステリシスによる区間化、前後余白と動画長でのはみ出し防止。
- lib/analysis_service.dart：competition モデルの読み込みと、Android のネイティブ解析呼び出し。
- lib/analysis_dialogs.dart：測定結果の表示（フレーム数、段階別の所要時間、動画1分あたりの換算、提案区間の一覧）。
- MainActivity.kt：`kite_clipper/analyze` チャンネル。同梱モデルをアプリ専用領域へ取り出し、ONNX セッションは使い回す。MediaMetadataRetriever で1秒ごとにフレームを取得（短辺224へ縮小→中央224x224切り出し、Python版と同じ前処理）、8枚ずつ推論、L2正規化して採点。段階ごとの所要時間を返す。解析は1件ずつ。
- 画面：編集画面の「保存する範囲」の右に「AI解析（測定）」。競技を選ぶと解析し、結果を表示する。

## この段階でやらないこと
- 提案区間を一覧へ追加すること、保存すること（表示のみ）。
- 進捗表示・中止（最大300フレーム＝5分で打ち切る）。
- Windows版の解析。
- 競技の自動判定、モデルの再学習。

## 測定手順（ビルド14・Android）
1. 動画を1本追加して開く。
2. 「AI解析（測定）」→ 競技を選ぶ（撮影内容に合うもの。分からなければ kite）。
3. 結果の「動画1分あたり：約○秒」を記録する。初回はモデル読み込みに時間がかかるため、**2回目も測る**。
4. 提案された区間が、実際の走行区間と合っているかをざっと確認する。
5. できれば長さの違う動画（1分程度と5分以上）で試す。5分以上の動画は300フレームで打ち切られる。
6. 解析中に端末が熱くなる・アプリが落ちる場合はその状況も記録する。

## 判断の目安
- 動画1分あたり60秒以内：実用的。次は進捗表示・中止・区間への追加を作る。
- 60〜180秒：実用ぎりぎり。フレーム間隔を2秒にする、解像度を下げるなどの軽量化を検討。
- 180秒超：この方式のままでは厳しい。フレーム取り出し方法の変更（MediaCodec連続デコード）やモデルの軽量化を検討。

## 実機での不具合と修正（ビルド14 → 15）
- 症状：Android実機で「AI解析（測定）」→ 競技 kite を選ぶと即失敗。
  メッセージ「FileNotFoundException This file can not be opened as a file descriptor; it is probably compressed」。
- 原因：同梱モデルの取り出し判定で `assets.openFd()` を使っていたため。APK内の同梱ファイルは圧縮されており、
  ファイルディスクリプタとして開けないので、サイズ問い合わせの時点で失敗していた。モデル本体・ONNX Runtime とは無関係。
- 修正：`openFd` をやめ、取り出し済みファイルの大きさを既知の値（CLIP_MODEL_BYTES = 89117001）と比較して判定する。
  取り出し結果の大きさが違えば失敗として扱い、途中で終わった古いコピーだけを置き換える。
- あわせて修正：エラー文が「AI解析に失敗しました：」と二重に付いていたため、Kotlin側の前置きを削除。
- 測定はビルド15で再実施する。
