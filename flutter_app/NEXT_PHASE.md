# 次段階：参照画像に沿った編集画面の仕上げ（承認前の案）

## 1. 要件定義
- 目的：最小実証の画面を、当初の参照画像に近い編集画面へ仕上げる。
- 対象：Flutter の Windows / Android 編集画面。
- 非対象：AI採点、複数候補管理、結合、タグ、保存エンジンの大幅変更。
- 制約：元動画と既存出力を維持。確認済みのPCM→AAC変換と範囲プレビュー連動を維持。
- 成功条件：スクロールなしで動画・再生操作・範囲調整・保存へアクセスでき、参照画像との比較結果を記録する。

## 2. 仕様
- 基準画像：../out/ui-redesign-20260912-01/04_preview.png。
- 入力：現在の1本のローカル動画。出力：従来の1区間保存。
- PC：左にクリップ概要、右に高さ制限付き動画、常時表示の再生操作と範囲欄。
- Android：操作欄優先の縦配置。横向きでは概要を縮小または省略。
- 開始・終了は実際の編集状態を表示し、操作した側の映像へ連動する。
- エラーは短い説明と展開式の診断情報に分け、長文で動画が押し出されないようにする。
- 連続サムネイルは後続の小タスクで実装する。取得中・失敗時はプレースホルダーとし、架空の映像を表示しない。
- 高速コピーによる保存境界の差を隠さない。今回フレーム精度を保証しない。
- 元仕様の複数候補ボタンは、機能が未実装の間は動作するように見せない。

## 3. 技術スタック
- Flutter / Dart、既存 media_kit / media_kit_video を継続。
- Android MediaExtractor / MediaMuxer / MediaCodec、Windows FFmpeg は変更しない。
- 新しい依存追加は予定しない。配布は引き続きWindowsビルドとテスト用APK。

## 4. 設計
- 編集状態と画面部品を分離し、再生操作・範囲欄・エラー表示を単体テスト可能にする。
- Playerの再生位置・再生状態を購読し、常時表示コントロールへ接続する。
- サムネイル取得は本再生のシークを妨げない方式を調査してから採用する。
- 動画切り替え時は古い処理結果を反映しない。メモリ使用量と取得枚数を制限する。
- UI調整は flutter_app/lib と test を中心に行う。

## 5. コミット単位のタスク
1. 参照画像と現行画面の差を比較し、配置・余白・色・文字の変更一覧を確定。
2. 常時表示の再生コントロールと、動画を圧迫しないエラー表示を実装・テスト。
3. 参照画像に合わせた外観調整と各画面サイズの回帰テスト。
4. 連続サムネイルの方式確認、最小実装、失敗時・動画切替時の安全化。
5. Windows / Androidビルド、実画面比較、利用者による操作確認。

まず1〜3を進める案。大きな機能拡張は別途合意する。
