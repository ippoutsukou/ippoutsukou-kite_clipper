# 次段階：一括保存（承認待ち）

## 1. 要件定義
- 目的：複数の動画・複数の区間を、1回の操作でまとめて保存する。
- 対象：Windows / Android。一覧の全動画の全区間（複数区間はビルド11で確認済み）。
- 非対象：結合（1本にまとめる）、再エンコード、チェックボックスによる個別選択、保存の並列実行、再起動後の再開、AI候補。
- 制約：
  - 1件ごとの保存処理（Windows FFmpeg高速コピー、Android MediaMuxer・PCM→AAC変換）の中身は変えない。
  - 原本・既存の保存済みファイルを上書き・削除しない。外部送信しない。新しい依存は追加しない。
- 成功条件：動画2本・計5区間を一括保存→保存先の1フォルダに5本が音声付きで作られ、途中の1件が失敗しても残りが保存され、結果一覧で成功・失敗が分かる。

## 2. 仕様
### 開始
- 下部に「すべて保存…」ボタンを追加（「この区間を保存」は残す）。
- 押すと確認ダイアログを表示：
  - 対象：「動画2本・区間5個（合計42.0秒）」
  - 対象外の件数：長さ未確認（まだ開いていない）動画は区間がないため対象外。「未確認の動画1本は含まれません」と表示。
  - 「保存済みの区間も保存し直す」チェック（初期値オフ＝保存済みはスキップ）。
  - 対象が0件なら開始ボタンを無効化し理由を表示。
- 「保存先を選ぶ…」で保存先フォルダを1回だけ選ぶ。キャンセルなら何も変えない。

### 保存先とファイル名
- 選んだフォルダの中に、実行ごとに新しいフォルダ `kite_clips_YYYYMMDD_HHMMSS` を作る（既存と重複したら末尾に _2, _3…）。
- ファイル名：`{一覧順3桁}_{元動画名（拡張子なし）}_区間{N}.mp4`（例 `001_GX010123_区間2.mp4`）。
  - ファイル名に使えない文字は `_` に置換し、元動画名部分は最大60文字。
  - 同名がある場合は上書きせず末尾に _2 を付ける。
- Windows：既存の保存と同じFFmpegの `-n`（上書き禁止）で書く。
- Android：フォルダ選択（システムのフォルダ選択画面）で得た場所に、フォルダとファイルを作って書く。

### 実行中
- 1件ずつ順番に保存（一覧順→区間番号順）。
- 画面上部に進捗「3 / 5 件目を保存中：GX010123 区間2」とバーを表示。
- 「中止」ボタン：いま保存中の1件が終わってから停止（書きかけのファイルを作らないため）。
- 実行中は動画追加・切替・区間操作・範囲変更・再生を無効化。再生は開始時に一時停止。
- Android：実行中は画面を消灯させない。アプリを閉じる・別アプリへ切り替えると中断される場合があることを開始前に案内。

### 失敗時
- 1件失敗しても残りを続ける。
- 失敗した保存先に未完成ファイルが残る場合があることを結果に表示（自動削除はしない）。
- 保存先フォルダ自体を作れない・書き込めない場合は、1件目の前に全体を中止してエラーを表示。

### 終了
- 結果ダイアログ：「成功4件・失敗1件・スキップ2件・中止で未実行0件」。
  - 失敗は「動画名 区間N：理由」を一覧表示。
  - 保存先フォルダのパス（AndroidはURIではなく「選んだフォルダ内の kite_clips_…」）を表示。
- 成功した区間は、その区間の保存結果を更新し、チップに緑のチェックを付ける。

## 3. 技術スタック
- Flutter / Dart。既存 file_selector（Windowsのフォルダ選択）・media_kit。
- Android：Kotlin。`ACTION_OPEN_DOCUMENT_TREE` と `DocumentsContract.createDocument`（標準API、依存追加なし）。
- 画面消灯防止：Android の `FLAG_KEEP_SCREEN_ON` を実行中だけ付ける（依存追加なし）。

## 4. 設計
- `BatchPlan`（純Dart）：一覧から対象を抽出（未確認除外・保存済みスキップ）、ファイル名の生成と文字置換、件数・合計秒数。
- `BatchRunner`（純Dart）：保存処理を受け取り、1件ずつ実行。中止フラグ、失敗の継続、結果集計。保存処理は差し替え可能にして、実際の動画なしでテストする。
- `ExportService`：
  - `pickBatchFolder()`：Windowsは getDirectoryPath＋実行フォルダ作成、Androidはネイティブのフォルダ選択＋フォルダ作成。
  - `exportInto(folder, fileName, source, range, duration)`：指定の場所に1件保存。
  - 既存の `export()`（1件保存）は変更しない。
- Android MainActivity：
  - 既存の書き込み処理（MediaMuxer部分）を「保存先URIを受け取る関数」へ切り出し、1件保存と一括保存で共用する。
  - 新メソッド `pickFolder`（ツリーURIとフォルダ作成）と `exportTo`（ファイル作成＋書き込み）。フォルダの使用許可はこの実行中のみ。
  - 切り出し前に既存ファイルを out/flutter-proof/batch-save-backup/ に退避。
- main.dart：確認ダイアログ、進捗表示、中止、結果ダイアログ。一括保存中は既存の `busy` で操作を無効化。

## 5. タスク（コミット単位）
1. `BatchPlan` と単体テスト（対象抽出、未確認除外、保存済みスキップ、ファイル名置換・長さ制限・重複、件数と合計秒数）。
2. `BatchRunner` と単体テスト（順序、中止は現在の1件後、失敗の継続、全体中止、結果集計）。
3. Windows：`pickBatchFolder` / `exportInto` と実エンジンテスト（合成動画2区間をフォルダへ保存し、長さと音声トラックを確認）。
4. Android：MainActivity の書き込み処理の切り出し、`pickFolder` / `exportTo`、画面消灯防止。1件保存が変わらないことを確認。
5. main.dart：「すべて保存…」、確認・進捗・中止・結果の各画面。
6. Windows版とAndroid APK（ビルド12）で利用者確認。

## 6. 決めてほしい点
1. 対象：全動画の全区間（個別選択なし）でよいか。
2. 保存済みの区間：初期値はスキップでよいか。
3. 保存先：実行ごとに `kite_clips_日時` フォルダを作る方式でよいか。
4. ファイル名：`001_元動画名_区間2.mp4` でよいか。
5. 失敗時は残りを続ける、中止は現在の1件の完了後、でよいか。
