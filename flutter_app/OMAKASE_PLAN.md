# おまかせモード（2026-09-17 承認・実装済み）

## 1. 要件定義
- 目的：動画を追加するだけで、AI解析と提案区間の追加まで自動で済ませる。
  利用者は結果を目で確認し、必要なら直してから「すべて保存…」を押す。
- 対象：Flutter の Windows / Android。
- 利用者の決定（2026-09-17）：
  - きっかけ：「動画を追加…」で動画を追加したとき。
  - 自動の範囲：提案区間を入れたところで止める（保存はしない）。
  - 競技モデル：おまかせ開始時に1つ選び、全動画に使う。
- 非対象：自動保存、フォルダ監視、動画ごとのモデル自動選択、結合、既存の手動AI解析の変更。
- 制約：元動画は変更しない。既存の区間（利用者が触ったもの）は消さない。
  4K動画で再生と解析が同時に動くと落ちる端末があるため、解析中は再生を止める（手動解析と同じ）。
- 成功条件：
  1. おまかせON で3本追加すると、3本とも順に解析され、提案区間が入る。
  2. 途中で中止すると、終わった動画の区間は残り、残りの動画は手を付けない。
  3. 提案0個・解析失敗の動画があっても止まらず、最後の一覧で分かる。

## 2. 仕様
### 画面
- 上部の「動画を追加…」の左に「おまかせ」スイッチを置く（狭い画面ではアイコン＋文字を短縮）。
- スイッチをONにすると設定ダイアログ：競技（kite / kite_static / wing / windsurf）とフレーム間隔（1秒/2秒）。
  既存のAI解析開始ダイアログと同じ選択肢。OKでON、キャンセルでOFFのまま。
- ON中はスイッチ横に選んだ競技名を表示（例「おまかせ：kite」）。
- ON/OFFと選んだ条件は、アプリを閉じても残す（前回の作業の復元と同じ保存先）。

### 動き
- ON中に「動画を追加…」で追加された動画**だけ**が対象（既に一覧にあった動画は対象外）。
- 1本ずつ順に処理：解析 → 提案区間を作る → その動画に追加。
  - 提案の作り方・追加の仕方は手動の「区間として追加」と同じ
    （触っていない初期区間は置き換え、上限20個を超える分は追加しない）。
  - 解析結果は動画ごとに保存し、手動のAI解析で「保存済みを使う」ができるようにする。
- 進捗ダイアログ：「おまかせ 2/3本目：GX014849.MP4　123/368枚」と中止ボタン。
  中止すると、処理中の動画は途中までの結果で提案を入れ、残りの動画は処理しない。
- 終了後に結果一覧を表示：動画ごとに「区間n個を追加」「提案0個」「失敗：理由」「中止のため未処理」。
  結果一覧の前に、最初に区間が入った動画を開いておく（なければ元の動画に戻す）。
- 解析中は他の操作（追加・保存・編集）をできなくする（手動解析と同じ）。

### 例外
- 解析に失敗した動画：区間は変更せず、結果一覧に理由を出して次の動画へ進む。
- 提案0個：区間は変更しない（初期区間のまま）。
- 動画の長さが未取得（まだ開いていない動画）：解析結果の長さを使って設定する。
- AI解析に対応していない環境：スイッチを表示しない。

## 3. 技術スタック
- 既存の Flutter / Dart、AnalysisService、ai_segments.dart をそのまま使う。新しい依存追加なし。

## 4. 設計
- `lib/omakase.dart`（新規）：設定（競技・間隔・ON/OFF）と、動画1本の処理結果を表す型。
  「解析結果→提案→追加」の部分は画面から切り離し、単体テストできる関数にする。
- `lib/main.dart`：`pick()` の追加後に、ON なら追加分を順に処理する流れを呼ぶ。
  手動の `runAnalysis()` と共通の部分（再生停止、進捗ダイアログ、解析記録の保存）は関数に切り出して共有する。
- `lib/session_store.dart`：おまかせ設定の保存・読み込み（形式のバージョンは互換を保つ）。
- `lib/analysis_dialogs.dart`：開始ダイアログを流用（ボタン文言だけ変える）、結果一覧ダイアログを追加。

## 進捗（2026-09-17・ビルド0917-2245）

- 1：`lib/omakase.dart` に設定（OmakaseSettings）を追加。作業記録（session.json）の `omakase` に保存。
  記録がない・不正な場合はOFF。形式のバージョンは1のまま（古い記録も読める）。

- 4：上部に「おまかせ」切り替え（ON時は競技名も表示、幅600未満は「おまかせ」のみ）。
  ONにするとき競技・間隔を選ぶ。進捗ダイアログに「n/m本目：ファイル名」。終了後に結果一覧。
- 5：中止後の動画は「未処理」、失敗した動画は理由を出して次へ。解析中は他の操作不可。
  開いている動画の区間を変えた場合は画面の範囲も合わせる（作業記録の書き出しで古い範囲が書き戻されるのを防ぐ）。

## 変更：提案0個の動画を保存・まとめる対象から外す（2026-11-25）
- きっかけ：テスターから「約20分の動画をまとめても17分程度にしかならない」との指摘。
  しきい値（kite 0.5/0.4/窓3）は変わっていない。提案0個の動画が全長の初期区間のまま残り、
  「1本にまとめて保存」「すべて保存」に入っていたのが原因（Python版は提案のある区間だけを切るため、0個の動画は入らなかった）。
- 仕様（PERSON_SCENES_PLAN §5 の案1をベースにした形）：
  - 最後まで解析して提案0個なら、動画に「提案なし」の印（`ClipItem.noProposals`）を付ける。おまかせ・手動のAI解析の両方が対象。
    途中まで（中止・打ち切り）の結果では付けない。
  - 印があり区間が初期状態（全体1区間・未保存）の動画は、一括保存・結合の対象から外す。区間は消さない（動画の扱いは変えない）。
  - 区間を変えれば対象に戻る。一覧の「︙」→「全体を対象に戻す」で印を消すこともできる。提案を入れると印は消える。
  - 一覧には「AIの提案なし（保存・まとめる対象外）」と表示する。
  - 保存・結合の確認画面に「AIの提案がなかった動画n本は含めません」と、
    「区間を決めていない動画n本は、全体（合計x秒）がそのまま入ります」を表示する（未解析の動画に気づけるように）。
  - 作業記録には `noProposals: true` を保存する（印がない動画は書かない。古い記録は印なしで読む）。
- 検証：静的解析成功、テスト133件成功（おまかせ・一括保存・結合・作業記録に追加）。
- 未確認：実画面での表示とテスターの素材での結果。
